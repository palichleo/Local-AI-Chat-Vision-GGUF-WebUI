# Atelier local

[English](README.md) | **简体中文** | [한국어](README.ko.md)

这是一款使用 HTML、CSS 和 JavaScript 编写的本地 GGUF 模型聊天与图像理解界面，也可选用 ComfyUI 生成图像。界面在浏览器中运行，由一个轻量的 Node.js 服务管理 llama.cpp。无需 npm 第三方依赖，不加载远程资源，也不使用遥测或云端 API。

应用界面目前使用法语。下文保留相关按钮的法语名称，方便在界面中找到对应功能。

## 启动

运行环境：**Node.js 22 或更高版本**、较新的浏览器，以及**支持 Qwen3.5 和视觉输入的较新版 llama-server**及其原生库。请使用与操作系统、处理器架构和硬件匹配的构建版本。应用不会自动下载模型或安装依赖。

Windows：双击 **Lancer-Windows.cmd**。

Linux：

```sh
sh lancer-linux.sh
```

以下命令在两个系统上均可使用：

```sh
node scripts/launch.mjs --open
```

在浏览器中打开 **http://127.0.0.1:8787**。请保持启动器窗口运行，更新后它仍会控制应用。关闭该窗口、按 `Ctrl+C` 或在 Configuration 中选择 **Fermer l’application**，都会停止应用及其模型并释放端口。再次启动会复用已运行的 Atelier 实例；若端口被其他服务占用，只会提示，不会终止该服务。如果浏览器没有自动打开，请手动输入地址。

无需运行 `npm install`，也可以使用 `npm start` 启动。



## 生成预览与参考图追踪

ComfyUI 运行时，聊天中显示有机动态占位画面，获取输出后即替换为原图；即使语言模型仍在重新加载也可显示。原图只用于浏览器展示，只有压缩副本传给模型。已知的声明尺寸决定占位画面比例；依赖未运行的自定义节点时先显示正方形，获得原图后采用真实尺寸，不猜测节点公式。启用减少动态效果时停止动画。

资源使用持久的 `Ref 1`、`Ref 2` 等标签，与模型目录保持一致，禁用或删除不会重新编号。原生读取工具每轮可读取最多八个不同资源，临时图片分别标识且不写入会话消息。生成记录标明真正传入 ComfyUI 的图片数量与工作流配置容量；文字工作流不能仅凭描述获得图片输入，需配置合适的工作流。

启动器每十秒发送一次控制心跳，短暂断线时重连。关闭终端仍会在短暂重连宽限期后停止本应用的模型和服务，保留历史与 ComfyUI 原图。


## ComfyUI 多参考图

导入 API 工作流时，在 **Entrées que le modèle peut modifier → Images de référence → Ajouter une entrée** 中添加图像输入。为每个输入选择图中已有的文件名字段，填写名称、用途说明，并设置是否必需。最多允许 64 个独立输入。应用不会猜测图像用途或自定义节点类型，也不会创建图连接或合并图像的节点；工作流本身必须已经支持这些输入。

模型通过原生工具将聊天图片与已启用的资源（或视频采样帧）分配给声明的输入。缺少必需项、来源冲突、重复目标、未知输入和已禁用资源会被拒绝。每个不同的压缩来源仅上传一次；同一次调用统一执行授权、显存交接和输出历史记录。未指定的可选输入保留工作流原值。现有单图工作流保持兼容；重新导入即可配置多图。导入界面原有的 `CLIPTextEncode` 提示词预选和 `SaveImage` 输出检测仍然保留，但新的图像映射不依赖节点类名。

打开 **Configuration**（配置），填写三个文件的完整路径，然后点击 **Enregistrer**（保存）：

**Parcourir…** 按钮会打开 Windows 文件选择器，或 Linux 上已安装的 zenity/kdialog。文件保持原位，不会上传；没有 Linux 选择器时可手动输入完整路径。

| 组件 | 原始模型版本的示例文件 |
|---|---|
| 推理引擎 | Windows 使用 `llama-server.exe`，Linux 使用 `llama-server` |
| Q6_K 模型 | [DeepSeek-V4-Pro-Qwen3.5-9B.Q6_K.gguf](https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/blob/main/DeepSeek-V4-Pro-Qwen3.5-9B.Q6_K.gguf) |
| FP16 视觉投影器 | [DeepSeek-V4-Pro-Qwen3.5-9B.mmproj-f16.gguf](https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/blob/main/DeepSeek-V4-Pro-Qwen3.5-9B.mmproj-f16.gguf) |

示例使用原始的 [Jackrong/DeepSeek-V4-Pro-Qwen3.5-9B](https://huggingface.co/Jackrong/DeepSeek-V4-Pro-Qwen3.5-9B) 版本。GGUF 文件位于[对应的量化模型仓库](https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/tree/main)。视觉投影器必须与模型匹配；仅使用文字聊天时，可将投影器路径留空。请保持推理引擎发行包中 DLL/SO 原生库的原有目录结构。

模型路径必须指向**文件本身**，而不是名称相似的文件夹。在 Windows 资源管理器中可使用“复制文件地址”或“复制为路径”；路径两侧的引号可以保留。Linux 通用路径示例：`/path/to/models/model.Q6_K.gguf`。

GGUF 文件不会上传到浏览器。文件路径保存在 `data/config.json` 中。源码发布包不包含个人配置文件。

某些 Qwen3.5 GGUF 导出文件在元数据中声明了 MTP 层，但并未包含该层的张量。应用会检查这一特定不匹配问题，并在可行时使用仅作用于内存的元数据覆盖。如果逐层元数据数组也包含这个缺失的层，应用会在 `data/model-cache` 中创建**兼容性副本**，修正元数据并保持权重的字节和存储位置不变。原始下载文件不会被修改。副本需要大约一个模型文件大小的额外磁盘空间，并会在后续启动时复用。实际包含 MTP 层的模型不会被修改。此机制不能修复缺失或损坏的模型权重。

部分 Ollama 安装所附带的 llama.cpp 引擎可以直接复用。应用会检测推理引擎旁 `cuda_v12` 或 `cuda_v13` 子目录中的 CUDA 库，不会启动或重新配置 Ollama 服务。如果环境中已经设置了 `GGML_BACKEND_PATH`，应用会保留该设置。

## 外观

界面默认为 **Night**（深色）模式。**Day / Night** 按钮位于 Configuration 设置内。选择会保存在本地 `data/preferences.json` 中，关闭或重启应用后仍然保留；该文件不会提交到 Git。加宽的 Configuration 按钮位于模型卡片下方。设置以圆角弹窗居中显示；点击外部或按 Escape 即可关闭。

上下文和最大输出使用保留原有固定档位的滑块；输出上限不能超过所选上下文，计算模式位于两者下方。空文件路径显示红色 **None**。初始输入框居中，建议按钮位于其下；开始对话后输入框移到底部。 各表面共用本地生成的原创 2048 × 2048 金属纹理，纹理保持静止。输入框和模型卡片的轻微指针光照在空闲时没有动画循环，并遵循触摸设备和减少动态效果的设置。

## 聊天与图像

发送第一条消息时，应用会自动启动已配置的模型及其视觉投影器（如有）。消息会等待加载完成，然后仅发送一次。已配置投影器时，可以在启动前添加图片。取消等待会将文字和图片恢复到输入框，模型仍会继续加载；加载失败时也会保留消息。手动启动和停止按钮仍然可用。

- 输入消息后按 Enter 发送；Shift+Enter 换行。
- 点击图像按钮添加 PNG/JPEG 图片，也可以拖放到输入区域，或在消息输入框中粘贴图片。
- 每条消息最多包含 64 张图片，每个源文件不超过64 MiB。浏览器会准备分析副本：单图最长边不超过 1,024 像素，所有图片共享四百万像素预算。它比较 PNG 与质量 `0.82`、白色背景的 JPEG，保留体积较小的结果。单次完整请求仍限制为 20 MiB 和 100 条消息；达到限制时请新建对话。
- **Réflexion**（思考）通过模型的聊天模板请求开启或关闭推理。实际效果取决于模型。收到的推理内容会显示在独立、可折叠的区域中。
- 方形按钮用于中断当前回复，已收到的文字会保留。
- 每次回复默认最多生成 4,096 个 token，包含推理，可在 Sortie maximale 中调整；达到输出或上下文上限时会显示截断提示。
- 模型回复支持常用 Markdown：标题、段落、粗体、斜体、删除线、列表、引用、简单表格、链接、行内代码和围栏代码块。回复流式输出时会同步更新格式。模型生成的原始 HTML 会被转义，不安全的链接协议会被拒绝，图片嵌入语法不会加载远程图片。

历史保存关闭时，刷新或关闭页面会丢失对话。启用后，可从历史列表恢复消息和图片。Configuration 会保留文件路径；关闭页面不会自动卸载模型。使用 Arrêter le modèle 或停止服务器可释放模型。

只有引用块和代码块在右上角提供小型复制图标，独立列预留空间，避免遮挡文本。引用复制纯文本，代码不包含语言标签和围栏符号。普通回答不显示整段复制按钮。复制失败会提示。对话与输入框共享响应式宽度，并考虑滚动条；滚动区域顶部和底部使用短渐变及轻微模糊，使衔接更柔和。

输入框下方的小型上下文指示器显示当前对话与草稿的用量、上下文上限以及预留的回答上限（含推理）。回答上限不代表保证可用的空间。输入暂停后才会计数，且不会启动已停止的模型。兼容的引擎无需生成回答即可计算实际输入，包括工具和图片。旧版引擎使用文本模板及分词器：**≈** 表示估算，**≥** 表示仅统计文本、图片成本未知。无法计数时显示 **—**。输入加回答上限接近容量时会提示，不会自动删减消息或修改设置。

关闭已修改的配置时，可选择保存、继续编辑或放弃修改；关闭按钮、Escape 和点击外部均会受到保护，关闭网页时也会显示浏览器警告。主题和历史偏好已即时保存，不会触发此提醒。保存主表单前，请完成或跳过尚未完成的工作流导入。


## 全局资源库与 Output

右侧浮动面板包含 **Ressources**（资源）和 **Output**（输出）标签，网格自动排列并可独立滚动，窄屏时移到聊天下方。

可拖入 PNG/JPEG/WebP 图片或 MP4/WebM 视频。应用将副本及压缩分析图保存在被 Git 忽略的 **data/resources/** 中。资源不依赖对话历史，切换对话、清空历史或重启后仍保留。悬停或键盘聚焦时显示删除按钮，触屏始终显示。删除只清除应用副本，不删除原始选中文件或 ComfyUI 原图。单张原图上限 64 MiB，单个视频上限 512 MiB。

新资源默认启用。启用状态和最多 300 字符的描述会保存；离开描述输入框或发送聊天前提交修改，未保存时关闭页面会警告。停用后模型当前目录与视觉读取工具均无法访问该资源，但已存在的对话文字不会被清除。

每次请求只注入已启用资源的精简文字目录。模型通过原生 **local_read_resource** 工具按需读取压缩图片；视觉副本仅用于当前轮，不进入保存的对话或后续轮次，文字分析仍保留。视觉读取要求对应投影器和支持原生工具调用的模型；纯文本模型仍可使用描述。不会按关键词强制触发生成。具有图片输入的兼容 Comfy 工作流也可在原有授权规则下引用已启用资源。

视频保留原文件以供本地播放；模型最多收到位于视频时长 10%、50%、90% 的三张压缩帧及时间点，不提供连续动作或音频分析。帧提取依赖浏览器编解码支持，原视频使用本地分段流播放。

Output 随当前对话及原有历史开关保存。卡片显示工作流和可展开的提示词。**Details** 展示原图、完整提示词、工作流、日期、seed、原始分辨率及可用执行参数。新生成还保存 Comfy 任务 ID、工作流摘要、Comfy 耗时及有限的标量输入快照。未知值不猜测；原图不可用时明确标注压缩预览。ComfyUI 原图不会由本应用删除。

## 使用本地 ComfyUI 生成图像

ComfyUI 工具**默认关闭**。先运行自己的本地 ComfyUI，再打开 **Configuration → ComfyUI**，启用连接并填写 API 地址。默认地址为 `http://127.0.0.1:8188`；SwarmUI 使用的 Comfy 后端可能采用其他本地端口，例如 `http://127.0.0.1:7821`。请填写实际后端的 API 地址。应用不会安装 ComfyUI、下载模型或附带第三方工作流。

在 ComfyUI 中使用 **File → Export (API)** 导出工作流副本，必要时先启用开发者选项，然后在 Configuration 中导入这个 **API 格式 JSON**。普通编辑器工作流 JSON（包括复杂子图）必须先通过 ComfyUI 导出，应用不提供转换器。导入副本保存在被 Git 忽略的 `data/workflows/` 中，原始工作流不变。设置名称、描述及保存图像的输出节点，并为必需的 `prompt` 以及支持的 `negative_prompt`、`seed`、`width`、`height`、`image` 明确绑定节点 ID 和输入名称。编辑图像的工作流可标记为需要参考图。模型只能更改这些映射的输入。宽高必须为 64 至 4,096 之间的 8 的倍数，种子必须是非负安全整数。

请使用**支持原生工具调用的 GGUF 模型及聊天模板**。应用会提供工具定义，并以 `--jinja` 启动 llama-server，无需手动补充该参数。用文字模仿工具调用不会执行工作流。对于有图像绑定的工作流，模型可按从零开始的索引选择已提供的参考图。

默认在每次执行前请求许可。可以仅批准一次，也可以全局允许已导入的工作流，随后在 Configuration 中撤销全局许可。默认**每个用户回合最多生成五次**，可调整为 1 至10,000次。确认界面会显示工作流和参数，并提供进度及取消操作。恢复历史不会自动重放批准或启动待处理任务。

运行时，应用先等待 ComfyUI 空闲，卸载聊天引擎和视觉投影器，再执行已批准的工作流。生成后释放 ComfyUI 模型，然后重启聊天引擎和投影器进行视觉检查；本地 ComfyUI 服务保持运行。视觉模型只收到压缩分析副本，可与原始要求及参考图比较，并在次数上限内调整生成。压缩丢失的细节可能无法检查，这一过程不会训练模型。**右侧画廊**显示工作流、提示词等信息，并可查看或下载 ComfyUI 输出原图。

应用会检查已保存的地址及常用本机端口8188和7821来自动查找 ComfyUI，不会扫描所有端口。找到后地址仍然显示，但不可编辑；点击 **Modifier** 可手动输入。地址右侧的 **Tester la connexion** 测试当前显示的地址。**Enregistrer** 会同时保存模型与 ComfyUI 设置并关闭弹窗，不再提供单独的 ComfyUI 保存按钮。仅修改 ComfyUI 时，无须停止聊天模型。

生成次数使用 −/+ 计数器与 **∞** 选项（后端最多10,000次）；上下文、消息和内存限制仍然适用。**Ajouter des workflows…** 可一次选择多个 API JSON 文件，并分别填写使用场景说明。也可在工作流列表修改说明，使用主保存按钮保存。模型会收到所有工作流的名称、说明和可修改输入，并按要求选择最合适的工作流。

## 可选对话历史与令牌限制

Configuration 中的 **Conserver les conversations**（保留对话）默认开启。关闭时，行为与此前相同：刷新或关闭页面会丢失对话。开启后，消息、推理和浏览器压缩后的图片会保存在项目的 `history/<对话ID>/` 中：`conversation.json` 与图片文件分开保存，相同图片在重复保存时不会重复复制。`history/` 和 `data/` 均被 Git 忽略，手动上传源码时也应排除这两个目录。

当前对话与已保存对话使用同一组等高列表行。当前对话固定在顶部并突出显示，旧对话以较淡样式显示日期。已保存的历史开关与生成次数选择会继续保留。

悬停或用键盘聚焦已保存的对话时，会显示垃圾桶按钮；触摸设备始终显示该按钮。确认后仅删除该对话、压缩副本及画廊链接，ComfyUI 输出的原图仍保留在原位置。

生成图像的历史只保存压缩检查副本和画廊元数据、链接。原图仍由 ComfyUI 的输出目录管理。**Supprimer l’historique** 会删除已保存的压缩副本、链接及对话，ComfyUI 原图不变。关闭历史时，画廊记录只保留在页面或服务器内存中。

可从侧边栏重新打开对话；窄屏可在 Configuration 中访问历史。应用会保存待处理消息、定期保存部分回复并保存最终回复。未完成发送的用户消息恢复为草稿，不会自动重发；部分助手回复会明确标注。强制关闭仍可能丢失最近尚未保存的流式内容。关闭历史只停止后续保存并隐藏列表，不会删除旧文件。红色 **Supprimer l’historique** 按钮可在确认后永久删除已保存的对话及其图片，即使历史保存已关闭也能使用；当前显示的对话会关闭，输入框草稿会保留。保存开关设置保持不变。对话中开启历史会保存当前交流；保存失败时仍保留页面内容，并阻止切换对话，直到保存成功或关闭历史。文件可在应用关闭后手动备份或删除。

**Contexte total**（总上下文）由消息、图像令牌、推理和回复共享；选项为 4,096 至 262,144。大上下文属于高级选项，实际容量取决于模型和内存/显存。**Sortie maximale**（最大输出）单独限制每次生成，包含推理，默认 4,096，最高可选 32,768 且不超过上下文。修改时需先停止模型，保存后在下次启动生效。恢复历史不会扩大模型上下文。

模型卡片边框用绿色表示就绪，红色表示停止或不可用，琥珀色表示加载或停止中。状态同时提供无障碍标签。

图片限制是**每条消息 64 张**。分析副本共享**四百万像素预算**，单图最长边不超过 1,024 像素。参考图越多，每张可分配的像素越少，并非向模型发送 64 张全分辨率图像。浏览器比较 PNG 与质量 `0.82` 的 JPEG，保留体积较小的结果；质量参数**不表示体积缩小 82%**，JPEG 使用白色背景。历史保存已准备好的字节，不会再次压缩。ComfyUI 原图由画廊单独提供查看和下载。

每次请求仍包含整个活动对话及旧图片。Base64 约增加三分之一体积，完整 JSON 请求仍限制为 **20 MiB 和 100 条消息**，其中也包括原生工具消息。减少图片字节数有助于存储和传输，但不会直接减少视觉令牌；图像尺寸和视觉编码器的处理方式才是关键。大量图片仍可能耗尽上下文，小细节也可能变得不可见。允许附加 64 张图片不代表每个模型、每种上下文设置都能有效处理全部图片。

## 内存与硬件

默认上下文为 **8,192 个 token**，并请求将所有可用模型层放到 GPU 上。初始配置面向 12 GB 显存的显卡，但实际占用取决于模型、上下文和图片。如果引擎报告内存或显存不足，请先停止引擎，再在 Configuration 中缩小上下文或减少 GPU 层数。

**CPU uniquement**（仅 CPU）使用处理器进行推理，并同时关闭视觉投影器的 GPU 卸载。速度可能明显较慢。应用面向 Windows/Linux，并不意味着所有计算机都有足够内存运行 9B 模型。没有 NVIDIA 显卡的计算机可使用 CPU 引擎，或适合自身 GPU 的 llama.cpp 构建版本。

应用不会执行或修改显卡解锁工具。启动、关闭和更新流程的冒烟测试通过 GitHub Actions 在 Windows 和 Ubuntu 上运行；硬件及模型兼容性仍取决于所选引擎。

## 故障排查

- **找不到文件：**检查完整路径，并确认下载已经完成。
- **引擎退出：**打开 Configuration → **Journaux du moteur**（引擎日志）。未知选项可能意味着引擎版本过旧；未知模型架构或不兼容的投影器需要匹配的引擎版本和模型文件。
- **无法检测到 CUDA：**检查引擎发行包、原生库和显卡驱动。设置 GPU 层数不代表一定会使用 GPU，实际卸载情况以引擎日志为准。
- **超出上下文：**新建对话，或在内存允许时增大上下文。应用不会静默删除历史消息。
- **ComfyUI 导入失败或工具不可用：**使用 File → Export (API) 导出，检查本地 API 地址并启用 ComfyUI，再确认提示词绑定和 GGUF 的原生工具支持。编辑图像还需要提供参考图及图像绑定。
- **连接中断：**检查终端后再刷新页面。未启用历史时，请先复制需要保留的文字；已启用时，请确认保存完成。
- **端口被占用：**可能已有其他实例使用 8787，请先关闭该实例再启动。

两个服务都只监听本机回环地址。控制接口会检查主机、来源和会话令牌。远程图片 URL 会被拒绝，llama.cpp 以离线模式启动，同时只允许一个生成请求。

## 更新提示

每次启动时，在后台检查一次本 GitHub 仓库的公开版本，四秒超时，不阻塞启动或聊天；离线时保持安静。存在更新的稳定版本时，Configuration 右侧显示浅蓝色按钮。

**点击按钮即自动安装更新。** 应用下载固定到 GitHub 提交的源码归档，检查版本与路径，备份将被替换的源码，停止空闲模型后在相同地址重启。页面会恢复对话、未完成回复状态、生成图像链接与输入草稿。生成或其他操作进行中时需要先等待完成。下载失败时原页面仍可使用；新版本无法启动时会恢复并重启旧版源码。

安装器保留 `data/`、`history/`、模型权重、ComfyUI 原图、Git 元数据以及受管理源码目录之外的文件。即使关闭常规历史，也会暂存 `data/update-session.json`，恢复页面后删除。源码备份与重启日志位于 `data/updates/`，安装状态位于 `data/update-status.json`。受管理源码目录中的自定义修改会被替换，旧副本保留在备份中；Git 元数据不会切换到下载的提交。不需要安装 Git，也不下载 npm 依赖，项目目录需要可写。

维护者：每次公开更新时递增 `package.json` 的 `version` 并发布到 `main`。相同、较旧或预览版本不显示按钮。检查与下载不会发送消息、图片、配置路径或硬件信息。

## 冒烟测试

```sh
node --test tests/*.mjs
```

也可以运行 `npm test` 或 `npm run smoke`；两者都会运行所有顶层测试文件，排除 `tests/fixtures/` 中的辅助脚本。测试使用**模拟 HTTP 引擎和本地 ComfyUI 响应**，检查聊天、访问限制、历史、工作流验证、原生工具批准、GPU 切换及恢复、画廊存储，以及启动、流式输出、图片、取消、CUDA 库检测和 MTP 兼容性处理。它不衡量真实模型或图像工作流的质量与速度。
