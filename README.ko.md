# Atelier local

[English](README.md) | [简体中文](README.zh-CN.md) | **한국어**

HTML, CSS, JavaScript로 만든 로컬 GGUF 모델 채팅 및 이미지 이해 인터페이스이며, 선택적으로 ComfyUI 이미지 생성을 사용할 수 있습니다. 브라우저에서 인터페이스를 사용하며, 작은 Node.js 서버가 llama.cpp를 관리합니다. npm 외부 패키지, 원격 리소스, 원격 측정 또는 클라우드 API를 사용하지 않습니다.

현재 앱 인터페이스는 프랑스어로 표시됩니다. 아래 설명에는 실제 버튼을 찾을 수 있도록 프랑스어 이름을 함께 적었습니다.

## 시작하기

**Node.js 22 이상**, 최신 브라우저, 그리고 **Qwen3.5와 이미지 입력을 지원하는 최신 llama-server 빌드 및 네이티브 라이브러리**가 필요합니다. 운영체제, 아키텍처, 하드웨어에 맞는 빌드를 사용하세요. 앱은 모델을 자동으로 다운로드하거나 의존성을 설치하지 않습니다.

Windows에서는 **Lancer-Windows.cmd**를 두 번 클릭합니다.

Linux에서는 다음을 실행합니다.

```sh
sh lancer-linux.sh
```

두 운영체제에서 공통으로 사용할 수 있는 명령은 다음과 같습니다.

```sh
node scripts/launch.mjs --open
```

브라우저에서 **http://127.0.0.1:8787**을 엽니다. 실행 창을 열어 두세요. 업데이트 후에도 앱 제어가 유지됩니다. 창을 닫거나 `Ctrl+C`를 누르거나 Configuration에서 **Fermer l’application**을 선택하면 앱과 모델이 종료되고 포트가 해제됩니다. 다시 실행하면 기존 Atelier 인스턴스를 재사용합니다. 다른 서비스가 8787 포트를 사용 중이면 알림만 표시하며 해당 서비스를 종료하지 않습니다. 브라우저가 자동으로 열리지 않으면 주소를 직접 입력하세요.

`npm install`은 필요하지 않습니다. `npm start`로 실행할 수도 있습니다.

## 파일 설정

**Configuration**(설정)을 열고 세 파일의 전체 경로를 입력한 뒤 **Enregistrer**(저장)를 누릅니다.

**Parcourir…** 버튼은 Windows 파일 선택기 또는 Linux에 설치된 zenity/kdialog를 엽니다. 파일은 이동하거나 업로드하지 않습니다. Linux 선택기가 없으면 전체 경로를 직접 입력하세요。

| 구성 요소 | 원본 모델 배포본의 예시 파일 |
|---|---|
| 추론 엔진 | Windows의 `llama-server.exe` 또는 Linux의 `llama-server` |
| Q6_K 모델 | [DeepSeek-V4-Pro-Qwen3.5-9B.Q6_K.gguf](https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/blob/main/DeepSeek-V4-Pro-Qwen3.5-9B.Q6_K.gguf) |
| FP16 비전 프로젝터 | [DeepSeek-V4-Pro-Qwen3.5-9B.mmproj-f16.gguf](https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/blob/main/DeepSeek-V4-Pro-Qwen3.5-9B.mmproj-f16.gguf) |

예시에는 원본 [Jackrong/DeepSeek-V4-Pro-Qwen3.5-9B](https://huggingface.co/Jackrong/DeepSeek-V4-Pro-Qwen3.5-9B) 배포본을 사용합니다. GGUF 파일은 [해당 양자화 저장소](https://huggingface.co/mradermacher/DeepSeek-V4-Pro-Qwen3.5-9B-GGUF/tree/main)에서 확인할 수 있습니다. 비전 프로젝터는 모델과 일치해야 합니다. 텍스트만 사용하려면 프로젝터 경로를 비워 두세요. 엔진의 DLL/SO 라이브러리는 배포본에 포함된 디렉터리 구조를 유지해야 합니다.

모델 경로는 이름이 비슷한 폴더가 아니라 **파일 자체**를 가리켜야 합니다. Windows 파일 탐색기의 **경로로 복사** 기능을 사용할 수 있으며, 경로를 둘러싼 따옴표도 허용됩니다. 일반적인 Linux 경로 예시는 `/path/to/models/model.Q6_K.gguf`입니다.

GGUF 파일은 브라우저로 업로드되지 않습니다. 파일 경로는 `data/config.json`에 저장됩니다. 개인 설정 파일은 소스 배포본에서 제외됩니다.

일부 Qwen3.5 GGUF 내보내기 파일은 실제 텐서가 없는 MTP 레이어를 메타데이터에 선언합니다. 앱은 이 특정 불일치를 확인하고, 가능한 경우 메모리에서만 적용되는 메타데이터 재정의를 사용합니다. 레이어별 메타데이터 배열에도 누락된 레이어가 포함되어 있으면 `data/model-cache`에 **호환성 복사본**을 만듭니다. 메타데이터를 수정하되 가중치의 위치와 바이트는 유지하며, 다운로드한 원본 파일은 변경하지 않습니다. 복사본에는 모델 파일 크기만큼의 추가 디스크 공간이 필요하고, 이후 실행에서 재사용됩니다. 실제 MTP 레이어가 있는 모델은 변경하지 않습니다. 이 기능으로 누락되거나 손상된 모델 가중치를 복구할 수는 없습니다.

일부 Ollama 설치에 포함된 llama.cpp 엔진을 직접 재사용할 수 있습니다. 앱은 엔진 옆의 `cuda_v12` 또는 `cuda_v13` 하위 디렉터리에서 CUDA 라이브러리를 찾습니다. Ollama 서비스를 시작하거나 재설정하지 않으며, 기존 `GGML_BACKEND_PATH` 환경 변수가 있으면 해당 설정을 유지합니다.

## 화면 테마

기본 테마는 **Night**(다크 모드)입니다. **Day / Night** 버튼은 Configuration 설정 안에 있습니다. 선택은 로컬 `data/preferences.json` 파일에 저장되어 앱을 닫거나 다시 실행해도 유지되며, 이 파일은 Git에 포함되지 않습니다. 넓어진 Configuration 버튼은 모델 카드 아래에 있습니다. 설정은 둥근 중앙 대화상자로 열리며, 바깥을 클릭하거나 Escape를 누르면 닫힙니다.

컨텍스트와 최대 출력은 기존의 고정된 값으로 이동하는 슬라이더입니다. 출력 상한은 선택한 컨텍스트를 넘지 않으며 계산 설정은 그 아래에 있습니다. 빈 파일 경로에는 빨간색 **None**이 표시됩니다. 시작 화면의 입력창은 중앙에 있고 제안 버튼은 그 아래에 배치됩니다. 대화가 시작되면 입력창은 하단으로 이동합니다. 표면은 로컬에서 생성한 독자적인 2048 × 2048 금속 질감을 공유하며, 질감은 정지 상태로 유지됩니다. 입력창과 모델 카드의 미세한 포인터 조명은 유휴 상태에서 애니메이션을 반복하지 않으며 터치 기기 및 동작 줄이기 설정을 따릅니다.

## 채팅과 이미지

첫 메시지를 보내면 설정된 모델과 비전 프로젝터(있는 경우)가 자동으로 시작됩니다. 메시지는 로딩이 끝날 때까지 기다린 뒤 한 번만 전송됩니다. 프로젝터가 설정되어 있으면 시작 전에도 이미지를 첨부할 수 있습니다. 대기 중인 메시지를 취소하면 텍스트와 이미지가 입력란으로 돌아오며 모델 로딩은 계속됩니다. 로딩에 실패해도 메시지는 보존됩니다. 수동 시작 및 중지 버튼도 계속 사용할 수 있습니다.

- 메시지를 입력하고 Enter로 전송합니다. Shift+Enter는 줄을 바꿉니다.
- 이미지 버튼으로 PNG/JPEG 파일을 첨부하거나, 입력 영역에 끌어 놓거나, 메시지 입력란에 이미지를 붙여 넣을 수 있습니다.
- 메시지당 최대 64장, 원본 파일당 최대64 MiB를 허용합니다. 브라우저는 긴 쪽이 최대 1,024픽셀인 분석용 사본을 만들며, 이미지 전체가 400만 픽셀 예산을 공유합니다. PNG와 품질 `0.82`의 흰색 배경 JPEG 중 용량이 작은 결과를 사용합니다. 전체 요청은 계속 20 MiB와 메시지 100개로 제한됩니다. 한도에 도달하면 새 대화를 시작하세요.
- **Réflexion**(추론)은 모델의 채팅 템플릿에 추론 활성화 또는 비활성화를 요청합니다. 실제 효과는 모델에 따라 다릅니다. 수신한 추론 내용은 별도의 접을 수 있는 영역에 표시됩니다.
- 네모 버튼은 현재 답변 생성을 중단합니다. 이미 받은 텍스트는 보존됩니다.
- 기본 생성 상한은 추론을 포함해 4,096토큰이며 Sortie maximale에서 조정할 수 있습니다. 출력 또는 컨텍스트 한도에 도달하면 안내가 표시됩니다.
- 모델 답변은 제목, 문단, 굵은 글씨, 기울임, 취소선, 목록, 인용문, 간단한 표, 링크, 인라인 코드와 코드 블록 등 일반적인 Markdown을 표시합니다. 스트리밍 중에도 서식이 갱신됩니다. 모델이 만든 원시 HTML은 이스케이프 처리하고, 안전하지 않은 링크 프로토콜은 거부하며, 이미지 삽입 문법으로 원격 이미지를 불러오지 않습니다.

기록 저장이 꺼져 있으면 페이지를 닫거나 새로고침할 때 대화가 사라집니다. 켜면 기록 목록에서 메시지와 이미지를 복원할 수 있습니다. 파일 경로 설정은 유지됩니다. 페이지를 닫아도 모델은 유지되며 Arrêter le modèle 또는 서버 종료로 해제합니다.

## 로컬 ComfyUI 이미지 생성

ComfyUI 도구는 **기본적으로 꺼져 있습니다**. 로컬 ComfyUI를 실행한 뒤 **Configuration → ComfyUI**에서 연결을 켜고 API 주소를 입력하세요. 기본값은 `http://127.0.0.1:8188`입니다. SwarmUI에서 사용하는 Comfy 백엔드는 `http://127.0.0.1:7821`과 같은 다른 로컬 포트를 사용할 수 있으므로 실제 백엔드 API 주소를 입력하세요. 앱은 ComfyUI를 설치하거나 모델을 다운로드하지 않으며 외부 제작 워크플로를 포함하지 않습니다.

ComfyUI의 **File → Export (API)**로 워크플로 사본을 내보내세요. 필요하면 개발자 옵션을 먼저 켠 뒤, 이 **API 형식 JSON**을 Configuration에서 가져옵니다. 복잡한 하위 그래프를 포함한 일반 편집기 워크플로 JSON은 ComfyUI에서 먼저 내보내야 하며 앱은 이를 변환하지 않습니다. 가져온 사본은 Git에서 제외되는 `data/workflows/`에 저장되고 원본 워크플로는 유지됩니다. 이름과 설명, 저장된 이미지의 출력 노드를 지정하고 필수 `prompt` 및 지원하는 `negative_prompt`, `seed`, `width`, `height`, `image`에 노드 ID와 입력 이름을 명시적으로 연결하세요. 이미지 편집 워크플로에는 참고 이미지 필수 여부를 설정할 수 있습니다. 모델은 이렇게 연결한 입력만 변경합니다. 너비와 높이는 64~4,096 범위의 8의 배수이며 시드는 음수가 아닌 안전한 정수여야 합니다.

**네이티브 도구 호출을 지원하는 GGUF 모델과 채팅 템플릿**이 필요합니다. 앱이 도구 정의를 제공하고 llama-server를 `--jinja`로 시작하므로 이 옵션을 따로 추가할 필요는 없습니다. 도구 호출을 흉내 낸 일반 텍스트는 워크플로를 실행하지 않습니다. 이미지 입력이 연결된 워크플로에서는 모델이 0부터 시작하는 인덱스로 제공된 참고 이미지를 선택할 수 있습니다.

기본적으로 매 실행 전에 승인을 요청합니다. 한 번만 승인하거나 가져온 워크플로를 전역으로 허용할 수 있으며, 전역 허용은 Configuration에서 취소할 수 있습니다. 기본값은 **사용자 턴당 최대 5회 생성**이며 1~10,000회로 조정할 수 있습니다. 승인 화면에 워크플로와 매개변수를 표시하고 진행 상황 및 취소 기능을 제공합니다. 기록을 복원해도 승인을 다시 적용하거나 대기 작업을 자동 실행하지 않습니다.

실행 시 ComfyUI가 유휴 상태가 될 때까지 기다린 뒤 채팅 엔진과 비전 프로젝터를 해제하고 승인된 워크플로를 실행합니다. 생성 후 ComfyUI 모델을 해제한 다음 채팅 엔진과 프로젝터를 다시 시작하여 이미지를 검토합니다. 로컬 ComfyUI 서비스는 계속 실행됩니다. 비전 모델에는 압축한 분석용 사본만 전달합니다. 원래 요청과 참고 이미지에 맞는지 비교하고 반복 한도 내에서 수정할 수 있지만, 압축으로 사라진 세부 사항은 놓칠 수 있으며 모델을 학습시키지는 않습니다. **오른쪽 갤러리**에서 워크플로와 프롬프트 정보를 확인하고 ComfyUI 원본 출력을 열거나 다운로드할 수 있습니다.

앱은 저장된 주소와 일반적인 로컬 포트8188 및7821만 확인하여 ComfyUI를 자동 검색하며 전체 포트를 스캔하지 않습니다. 발견된 주소는 읽기 전용으로 표시되고 **Modifier**를 누르면 직접 입력할 수 있습니다. 주소 오른쪽 **Tester la connexion**은 현재 표시된 주소를 테스트합니다. **Enregistrer**는 모델과 ComfyUI 설정을 함께 저장하고 대화상자를 닫으며 별도의 ComfyUI 저장 버튼은 없습니다. ComfyUI 설정만 바꿀 때는 채팅 모델을 중지할 필요가 없습니다.

생성 횟수는 −/+ 카운터와 **∞** 옵션으로 설정합니다(백엔드 상한10,000회). 컨텍스트, 메시지 및 메모리 한도는 그대로 적용됩니다. **Ajouter des workflows…**에서 여러 API JSON 파일을 선택하고 각 워크플로의 용도를 설명할 수 있습니다. 목록에서 설명을 수정한 뒤 기본 저장 버튼으로 저장할 수도 있습니다. 모델은 등록된 이름, 설명, 지원 입력을 받아 가장 적합한 워크플로를 선택하도록 지시받습니다.

## 선택적 대화 기록과 토큰 제한

Configuration의 **Conserver les conversations**(대화 보관)는 기본적으로 켜져 있습니다. 끄면 이전과 같이 페이지를 닫거나 새로고침할 때 대화가 사라집니다. 켜면 메시지, 추론, 브라우저에서 압축한 이미지를 프로젝트의 `history/<대화ID>/`에 저장합니다. `conversation.json`과 이미지 파일은 분리되며, 반복 저장 시 같은 이미지를 다시 복사하지 않습니다. `history/`와 `data/`는 Git에서 제외됩니다. 소스를 수동 업로드할 때도 두 폴더를 제외하세요.

현재 대화와 저장된 대화는 같은 높이의 목록으로 표시됩니다. 현재 대화는 맨 위에서 강조되고 이전 대화는 차분한 스타일과 날짜로 구분됩니다. 이전에 저장한 기록 및 생성 횟수 설정은 유지됩니다.

저장된 대화에 마우스를 올리거나 키보드로 초점을 맞추면 휴지통 버튼이 나타나며, 터치 기기에서는 항상 표시됩니다. 확인 후 해당 대화와 압축 사본, 갤러리 링크만 삭제합니다. ComfyUI의 원본 출력 파일은 원래 위치에 남습니다.

생성 이미지 기록에는 압축한 검토용 사본과 갤러리 메타데이터·링크만 저장합니다. 원본은 ComfyUI 출력 저장소에 남습니다. **Supprimer l’historique**는 대화와 함께 저장한 압축 사본과 링크를 지우며 ComfyUI 원본 파일은 변경하지 않습니다. 기록을 끄면 갤러리 기록은 페이지 또는 서버 메모리에만 남습니다.

사이드바에서 대화를 다시 열 수 있으며 좁은 화면에서는 Configuration에서 기록에 접근합니다. 대기 중인 사용자 메시지, 주기적인 부분 응답, 최종 응답을 저장합니다. 미완료 사용자 메시지는 초안으로 복원하며 자동 재전송하지 않습니다. 부분 응답은 표시됩니다. 강제 종료하면 가장 최근의 미저장 스트리밍 내용은 잃을 수 있습니다. 기록을 끄면 이후 저장을 멈추고 목록을 숨기며 기존 파일은 삭제하지 않습니다. 빨간색 **Supprimer l’historique** 버튼은 확인 후 저장된 대화와 이미지를 영구 삭제하며 기록 저장이 꺼져 있어도 사용할 수 있습니다. 표시 중인 대화는 닫히고 입력 중인 초안은 유지되며, 저장 옵션은 바뀌지 않습니다. 대화 도중 켜면 현재 교환 내용을 저장합니다. 저장에 실패하면 페이지의 대화를 유지하고, 저장에 성공하거나 기록을 끌 때까지 다른 대화로 이동하지 않습니다. 앱을 닫은 뒤 파일을 직접 백업하거나 삭제할 수 있습니다.

**Contexte total**(총 컨텍스트)은 메시지, 이미지 토큰, 추론과 응답이 공유합니다. 4,096~262,144 옵션을 제공하지만 큰 값은 고급 옵션이며 실제 사용 가능 여부는 모델과 RAM/VRAM에 달려 있습니다. **Sortie maximale**(최대 출력)는 추론을 포함한 응답별 생성 상한으로, 기본 4,096이며 컨텍스트 이내에서 최대 32,768까지 선택합니다. 모델을 중지한 뒤 변경하고 저장하면 다음 시작부터 적용됩니다. 기록 복원이 모델의 컨텍스트를 늘리지는 않습니다.

모델 카드 테두리는 준비 상태에서 녹색, 중지되거나 연결할 수 없을 때 빨간색, 로딩·종료 중에는 호박색입니다. 접근성 레이블도 상태를 알려줍니다.

이미지 제한은 **메시지당 64장**입니다. 분석용 이미지는 **400만 픽셀 예산**을 공유하며 각 이미지의 긴 변은 최대 1,024픽셀입니다. 참고 이미지가 많을수록 각 이미지에 할당되는 픽셀이 줄어들며 64장을 모두 원본 해상도로 보내지는 않습니다. 브라우저가 PNG와 품질 `0.82`의 JPEG를 비교해 용량이 작은 결과를 사용합니다. 품질 값은 **용량을 82% 줄인다는 뜻이 아니며**, JPEG는 흰색 배경을 사용합니다. 기록에는 분석용으로 준비된 바이트를 그대로 저장하고 다시 압축하지 않습니다. ComfyUI 원본은 갤러리에서 별도로 열거나 다운로드합니다.

각 요청은 이전 이미지를 포함한 활성 대화 전체를 전송합니다. Base64는 약 3분의 1의 용량을 추가하며 전체 JSON 요청은 네이티브 도구 메시지를 포함해 계속 **20 MiB와 메시지 100개**로 제한됩니다. 이미지 파일 크기를 줄이면 저장과 전송에는 도움이 되지만 이미지 토큰이 직접 줄어들지는 않으며 해상도와 비전 인코더의 처리가 좌우합니다. 이미지가 많으면 컨텍스트가 부족하거나 작은 세부 사항을 놓칠 수 있습니다. 64장 첨부를 허용한다고 해서 모든 모델과 컨텍스트 설정이 전체 이미지를 유용하게 처리할 수 있다는 보장은 없습니다.

## 메모리와 하드웨어

기본 컨텍스트는 **8,192토큰**이며 사용 가능한 모든 모델 레이어의 GPU 배치를 요청합니다. 초기 설정은 VRAM 12 GB 그래픽 카드를 대상으로 하지만, 실제 사용량은 모델, 컨텍스트, 이미지에 따라 달라집니다. 엔진이 메모리 부족을 보고하면 먼저 중지한 뒤 Configuration에서 컨텍스트를 줄이거나 GPU 레이어 수를 낮추세요.

**CPU uniquement**(CPU 전용)은 프로세서에서 추론하며 비전 프로젝터의 GPU 오프로딩도 끕니다. 속도가 크게 느려질 수 있습니다. Windows/Linux를 지원하도록 작성되었다고 해서 모든 컴퓨터에 9B 모델을 실행할 메모리가 충분한 것은 아닙니다. NVIDIA GPU가 없는 컴퓨터에서는 CPU 엔진이나 해당 GPU에 맞는 llama.cpp 빌드를 사용할 수 있습니다.

앱은 GPU 잠금 해제 도구를 실행하거나 수정하지 않습니다. Windows에서는 로컬 실행을 확인했지만, Linux에서의 실제 실행은 아직 확인하지 않았습니다.

## 문제 해결

- **파일을 찾을 수 없음:** 전체 경로와 다운로드 완료 여부를 확인하세요.
- **엔진 종료:** Configuration → **Journaux du moteur**(엔진 로그)를 확인하세요. 알 수 없는 옵션은 엔진이 오래된 버전이라는 뜻일 수 있습니다. 지원하지 않는 모델 아키텍처나 호환되지 않는 프로젝터에는 맞는 엔진 빌드와 파일이 필요합니다.
- **CUDA를 찾지 못함:** 엔진 배포본, 라이브러리, 드라이버를 확인하세요. GPU 레이어 수를 요청하는 것만으로 GPU 사용이 보장되지는 않습니다. 실제 오프로딩은 엔진 로그에서 확인할 수 있습니다.
- **컨텍스트 초과:** 새 대화를 시작하거나 메모리가 허용하는 범위에서 컨텍스트를 늘리세요. 앱은 기록을 알리지 않고 삭제하지 않습니다.
- **ComfyUI 가져오기 실패 또는 도구 사용 불가:** File → Export (API)로 내보내고 로컬 API 주소와 ComfyUI 활성화를 확인한 다음 프롬프트 연결과 GGUF의 네이티브 도구 지원을 확인하세요. 이미지 편집에는 제공된 참고 이미지와 이미지 입력 연결도 필요합니다.
- **연결 중단:** 터미널을 확인한 뒤 페이지를 새로고침하세요. 기록을 끈 경우 필요한 텍스트를 먼저 복사하고, 켠 경우 저장이 끝났는지 확인하세요.
- **포트 사용 중:** 다른 인스턴스가 8787을 사용 중일 수 있습니다. 해당 인스턴스를 종료한 뒤 다시 시작하세요.

두 서비스는 루프백 주소에서만 연결을 받습니다. 제어 API는 호스트, 출처와 세션 토큰을 확인합니다. 원격 이미지 URL은 거부하고 llama.cpp는 오프라인 모드로 시작합니다. 한 번에 하나의 생성 요청만 허용합니다.

## 업데이트 알림

실행할 때마다 이 GitHub 저장소의 공개 버전을 백그라운드에서 한 번 확인합니다. 제한 시간은 4초이며 시작이나 채팅을 막지 않고 오프라인에서는 조용히 넘어갑니다. 더 최신의 안정 버전이 있으면 Configuration 오른쪽에 연한 파란색 버튼이 나타납니다.

**버튼을 클릭하면 업데이트가 자동으로 설치됩니다.** GitHub 커밋에 고정된 소스 압축 파일을 내려받아 버전과 경로를 검사하고, 교체할 소스를 백업한 뒤 유휴 모델을 중지하고 같은 주소에서 앱을 다시 시작합니다. 대화, 미완료 응답 상태, 생성 이미지 링크와 입력 초안이 복원됩니다. 생성이나 다른 작업이 진행 중이면 완료될 때까지 기다려야 합니다. 다운로드 실패 시 기존 페이지를 계속 사용할 수 있으며 새 버전이 시작되지 않으면 이전 소스를 복원하고 다시 실행합니다.

설치기는 `data/`, `history/`, 모델 가중치, ComfyUI 원본, Git 메타데이터와 관리 대상 소스 폴더 밖의 파일을 보존합니다. 일반 기록을 꺼도 복원될 때까지 `data/update-session.json`에 임시 세션을 저장합니다. 소스 백업과 재시작 로그는 `data/updates/`, 설치 상태는 `data/update-status.json`에 남습니다. 관리 대상 소스 폴더의 직접 수정은 교체되며 이전 사본은 백업에 보관됩니다. Git 메타데이터는 다운로드한 커밋으로 이동하지 않습니다. Git 설치나 npm 의존성 다운로드는 필요하지 않으며 프로젝트 폴더에 쓰기 권한이 있어야 합니다.

관리자: 공개 업데이트마다 `package.json`의 `version`을 올려 `main`에 게시하세요. 같거나 오래된 버전, 미리 보기 버전에는 버튼이 표시되지 않습니다. 확인과 다운로드 과정에서 메시지, 이미지, 설정 경로나 하드웨어 정보를 보내지 않습니다.

## 스모크 테스트

```sh
node --test tests/*.mjs
```

`npm test` 또는 `npm run smoke`를 사용할 수도 있습니다. 둘 다 최상위 테스트 파일 전체를 실행하며 `tests/fixtures/`의 보조 스크립트는 제외합니다. 테스트는 **모의 HTTP 엔진과 로컬 ComfyUI 응답**으로 채팅, 접근 제한, 기록, 워크플로 검증, 네이티브 도구 승인, GPU 전환·복구, 갤러리 저장과 함께 시작, 스트리밍, 이미지, 취소, CUDA 라이브러리 탐색 및 MTP 호환성 처리를 확인합니다. 실제 모델이나 이미지 워크플로의 품질과 속도를 측정하지는 않습니다.
